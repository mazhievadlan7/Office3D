# Hermes Agent: запуск и эксплуатация

Hermes Agent от Nous Research — бэкенд Office3D по умолчанию. Архитектура и
причины решений описаны в [`hermes-platform.md`](hermes-platform.md); здесь —
как это запустить, проверить и обслуживать.

## Как устроено

```text
Браузер ⇄ Office3D (server/index.js) ⇄ адаптер Hermes (в том же процессе) ⇄ Hermes
                                            server/hermes/*          API :8642
                                                                     панель :9119 через hermes-gate
```

- Каждый агент офиса — отдельный профиль Hermes со своей памятью, навыками,
  ключами и `SOUL.md`. Главный агент — профиль `default`.
- Ход агента — запуск Hermes (`/v1/runs`): ответ приходит потоком, вызовы
  инструментов видны в журнале запусков, опасные команды ждут одобрения,
  запуск можно остановить.
- История разговоров хранится в сессиях Hermes, задачи по расписанию — в
  расписании Hermes (`/api/jobs`).
- Браузер не видит ни одного ключа Hermes: адаптер работает на сервере
  Office3D и принимает подключение только от своего прокси (секрет
  генерируется при каждом запуске).

## Запуск в Docker (рекомендуется)

1. Скопируйте `.env.example` в `.env` и задайте секреты — каждый командой
   `openssl rand -hex 32`:

   ```env
   STUDIO_ACCESS_TOKEN=...
   HERMES_API_KEY=...
   HERMES_DASHBOARD_TOKEN=...
   OFFICE3D_HERMES_KEY_SECRET=...
   OFFICE3D_UPDATER_TOKEN=...
   ```

2. Запустите:

   ```bash
   docker compose up -d
   ```

   Поднимутся четыре контейнера: `office3d-hermes` (Hermes),
   `office3d-hermes-gate` (единственный вход в панель Hermes), `office3d`
   (офис, порт 3000 на loopback) и `office3d-updater` (обновления Hermes).

3. Один раз настройте модели и ключи провайдера в Hermes:

   ```bash
   docker compose exec hermes hermes setup
   ```

   Новые агенты копируют эту настройку из главного профиля.

4. Откройте офис через обратный прокси с TLS (см. [`deployment.md`](deployment.md)).
   Экран подключения выбирать не нужно: при заданном `HERMES_API_URL` сервер
   сам подключает Hermes.

## Запуск без Docker

Нужен установленный Hermes (`hermes` в `PATH`) с настроенной моделью и те же
секреты в `.env`, кроме `STUDIO_ACCESS_TOKEN`:

```bash
npm run hermes-local
```

Скрипт поднимает шлюз Hermes (API на `127.0.0.1:8642`), панель Hermes
(`127.0.0.1:9119`) и сервер разработки Office3D, а по Ctrl+C останавливает всё.
Занятый порт — ошибка, а не повод запустить второй экземпляр: два Hermes на
одном `HERMES_HOME` портят память друг друга.

## Модели, провайдеры и ключи

«Настройки офиса» → «Модели и провайдеры Hermes» (видно при подключении к
Hermes). Всё берётся из каталога самого Hermes:

- **Модель главного агента** — новые сотрудники копируют её при найме.
  Модель любого агента меняется в его настройках («Модель агента»).
- **Вход через аккаунт** — Nous Portal и другие провайдеры с входом по коду:
  ссылка и код показываются прямо в офисе. Вход делается один раз, в главном
  профиле; остальные агенты пользуются им через общий пул учётных данных Hermes.
- **Ключи провайдеров и инструментов** — ключ проверяется у провайдера, где
  это возможно, и записывается в `.env` всех агентов сразу. Из офиса можно
  менять только ключи категорий «провайдер», «инструмент» и «навык»; ключ
  API-сервера, токены мессенджеров и служебные настройки недоступны.
  Значения ключей в браузер не передаются — только отметка «задан» и
  сокращённый вид, который показывает сам Hermes.

Новый сотрудник получает конфигурацию, ключи, навыки и знания о человеке
(`USER.md`) главного агента, но не его собственные заметки (`MEMORY.md`):
память у каждого агента своя.

## Навыки

Настройки агента → «Возможности» → «Навыки Hermes»:

- все навыки из профиля агента с переключателями: выключенный навык агент не
  видит;
- «Каталог» — официальные навыки Hermes, поиск — по всем источникам Hermes
  Skills Hub.

Устанавливает сам Hermes: скачивает навык, держит его в карантине и
проверяет. Офис заранее показывает результат той же проверки безопасности:

- то, что Hermes запрещает, установить нельзя;
- для навыков, которые требуют внимания, установка возможна только после
  явного подтверждения «Установить, я проверил».

Можно поставить навык одному агенту или всей команде. Ход установки виден в
офисе.

## Миссия и доска задач

- Миссия задаётся над доской задач («Миссия организации»). Офис записывает её
  вместе с правилами роли в `SOUL.md` каждого агента — отдельным блоком между
  маркерами `office3d:organization`; не правьте этот блок вручную, офис
  перепишет его при следующем подключении. Характер агента правится в его
  настройках, как раньше.
- Главный агент получает набор инструментов `kanban` и раскладывает работу на
  доске; остальные агенты задач не ставят и работают над назначенными.
- Hermes технически разрешает любому исполнителю создавать задачи. Поэтому
  Office3D каждые 15 секунд проверяет доску: задача, созданная не
  руководителем и не главным агентом, возвращается в «Разбор» без
  исполнителя, с комментарием, кто её предложил и кого — в исполнители. В
  работу она пойдёт, когда главный агент или руководитель назначит
  исполнителя; после этого Office3D её больше не трогает.
- Доска офиса — это канбан Hermes. Задача без исполнителя попадает в «Разбор»
  (triage) и ждёт главного агента или руководителя; назначенную задачу
  диспетчер Hermes запускает сам. Задачи Hermes появляются в офисе в течение
  нескольких секунд.

## Автономия и дневной бюджет

Под миссией на доске задач — строка «Автономия»: режим, расход за сегодня,
кнопки «Обзор сейчас», «Пауза» и «Настроить».

- **Режимы.** «Выключена» — агенты работают только над тем, что им дали.
  «По расписанию» — главный агент раз в заданный интервал (от 15 минут до
  суток) разбирает предложения задач, снимает блокировки и ставит следующие
  шаги к миссии. «Непрерывно» — главного зовут, как только на доске
  кончается работа или сотрудники предлагают новые задачи; пока обзоры
  ничего не меняют, пауза между ними растёт (15 → 30 → 60 минут… до
  интервала расписания). Обоим режимам можно задать рабочие часы.
- **Обзоры** идут в отдельной сессии главного агента на каждый день
  (`agent:main:autonomy-ГГГГ-ММ-ДД`) и не засоряют разговор с ним в офисе.
- **Дневной бюджет** в долларах (0 — без лимита, по умолчанию 5 $). Расход —
  рост суммарной стоимости всех агентов по оценке Hermes с полуночи в
  выбранном часовом поясе (`OFFICE3D_TIMEZONE` или настройка). Когда бюджет
  исчерпан, автономные обзоры прекращаются до полуночи, а если отмечено —
  встаёт и доска: диспетчер Hermes не берёт новые задачи, начатые
  доделываются. Ваши разговоры с агентами бюджет не ограничивает. Hermes
  оценивает не всех провайдеров: у подписки (например, Nous Portal) стоимость
  может быть нулевой, и тогда бюджет её не видит. Если Hermes не отдаёт
  статистику, при заданном бюджете автономия не запускается.
- **Пауза** останавливает автономные обзоры и доску до снятия. Доска
  ставится на паузу через `kanban.dispatch_profiles` в `config.yaml`
  главного профиля (пустой список — никто не берёт задачи); после первой
  паузы Office3D держит там список всей текущей команды.
- **Разбор задач** — работа главного агента: Office3D выключает собственный
  LLM-разборщик Hermes (`kanban.auto_decompose: false`), иначе он сам
  раздавал бы задачи из «Разбора» в обход главного.

## Совещания

На Hermes переговорная офиса проводит настоящие совещания. Созвать его можно
тремя способами: кликнуть по столу в переговорной, сказать или написать
главному агенту фразу вроде «собери всех на совещание по рекламе» (тогда
фраза и станет темой), либо главный агент созовёт его сам инструментом
`office_call_meeting`.

- Ведёт совещание сервер Office3D, так что открытая вкладка офиса для него
  не нужна. Пока агенты идут в переговорную, совещание ждёт, пока все
  рассядутся, но не больше 20 секунд.
- Главный агент открывает совещание. Затем каждый участник по очереди
  отвечает живой репликой модели и видит стенограмму предыдущих
  выступлений. В конце главный подводит итог, ставит договорённые задачи на
  доску (с исполнителями из участников) и коротко говорит, кто что делает.
- Реплика говорящего появляется над ним в 3D. На экране совещания видны
  тема, все реплики и итог; кнопка «Остановить» завершает совещание досрочно.
- Каждая реплика — отдельный запуск Hermes в своей сессии совещания
  (`agent:<id>:meeting-<id совещания>`), поэтому разговоры с агентами в
  офисе не засоряются. На реплику даётся до трёх минут. Одновременно идёт
  одно совещание, в нём не больше восьми участников. Последние 20 совещаний
  со стенограммами хранятся в состоянии офиса.
- Совещание, которое созвал главный агент, не начнётся, если дневной бюджет
  автономии исчерпан. Совещание, созванное вами, начнётся всегда.

## Голос

- **Говорить с главным агентом:** удерживайте Alt. **Обратиться ко всей
  команде:** удерживайте Alt+Shift. Речь распознаётся один раз, а
  сообщение с пометкой «руководитель обратился ко всем» уходит каждому
  агенту. Каждый отвечает своим голосом, задачи по-прежнему раздаёт главный.
- **Голоса команды** настраиваются в «Настройках офиса». У каждого агента
  свой голос. «Авто» подбирает постоянный голос по агенту и не повторяет
  голос главного, поэтому на совещании слышно, кто говорит.
- **Озвучивается:** ответы агентов в офисе, реплики совещания по очереди
  (каждая — голосом говорящего), объявления главного агента
  (`office_announce`) и его предложения нанять или уволить. Автономные
  обзоры не озвучиваются.
- **Диалог с главным агентом:** по его правилам он уточняет неясное,
  пересказывает план и спрашивает согласия. После согласия ставит задачи на
  доску и сообщает команде объявлением или созывает совещание.
- **Провайдеры** выбираются на сервере, для каждого направления отдельно:
  - ElevenLabs — распознавание Scribe и голоса, один ключ `ELEVENLABS_API_KEY`;
  - свой сервер с API OpenAI (`/audio/transcriptions` и `/audio/speech`) —
    путь к бесплатному локальному голосу рядом с офисом, например
    faster-whisper для распознавания и Kokoro для голосов
    (`OFFICE3D_STT_PROVIDER`/`OFFICE3D_TTS_PROVIDER=openai-compatible`,
    `OFFICE3D_VOICE_API_URL` и остальное — в `.env.example`);
  - OpenClaw — только распознавание, для офисов на OpenClaw.

  Без `ELEVENLABS_API_KEY` и без своего сервера распознавание пытается идти
  через OpenClaw; на установке только с Hermes задайте один из вариантов
  выше. Что настроено, видно в «Настройках офиса».
- Ключи остаются на сервере. Браузер получает короткие сообщения об
  ошибках без подробностей провайдера. Распознавание ограничено 30
  запросами в минуту с клиента, озвучка — 60.

## Одобрение опасных действий

Hermes останавливает агента перед опасной командой (удаление, системные
изменения и т. п.) и ждёт решения до пяти минут.

- **Действия главного агента** решаете вы: карточка «Требуется одобрение»
  появляется в его чате.
- **Действия остальных сотрудников** сначала решает главный агент. Он
  получает запрос в отдельной сессии (`agent:main:approvals-ГГГГ-ММ-ДД`) и
  отвечает инструментом `office_decide_approval`:
  - обычные рабочие шаги одобряет;
  - лишнее отклоняет;
  - важное (необратимое, деньги, удаление данных, доступы, публикации,
    сообщения от имени организации) передаёт вам с объяснением.

  На карточке тогда написано «Главный агент передал решение вам: …», и это
  же произносится голосом.
- Если главный агент не решил за 2,5 минуты или его обзор не удался, запрос
  приходит вам с пометкой «Решение за вами».
- Все решения — чьё, какое и почему — пишутся в журнал (последние 200,
  метод `org.approvals.log`).
- Задачи с доски, которые выполняет диспетчер Hermes, в эту цепочку не
  попадают. В неинтерактивных исполнителях Hermes отклоняет опасные команды
  сразу (`approvals.single_query_mode: deny` по умолчанию). Исполнитель
  сообщает об этом на доске, и такую задачу разбирает главный агент.

## Команда: найм и увольнение

Менять состав команды могут только руководитель и главный агент, и главный —
только с согласия руководителя:

- Руководитель нанимает и увольняет сам, как раньше, кнопками офиса.
- Главный агент предлагает инструментами Office3D (`office_propose_hire`,
  `office_propose_dismiss`) и обязан назвать причину. В офисе появляется
  карточка «Главный агент предлагает нанять / уволить» с причиной, полем
  комментария и кнопками «Одобрить» и «Отклонить». До решения в команде
  ничего не меняется; одновременно ждать решения может не больше десяти
  предложений.
- Одобренное предложение выполняет сам Office3D: найм — тем же путём, что и
  кнопка офиса (с характером, который предложил главный агент), увольнение —
  сняв с сотрудника незавершённые задачи и вернув их на разбор с пометкой.
- О решении главный агент узнаёт сообщением «[Office3D] …» в своём чате офиса
  и может сразу действовать: ввести новичка в курс дела, перераспределить
  задачи. Историю решений он видит инструментом `office_proposals`.

Инструменты приходят к агентам через MCP-сервер Office3D — отдельный
внутренний порт (`OFFICE3D_MCP_PORT`, по умолчанию 3010), который никогда не
публикуется наружу. Каждый агент входит со своим токеном, выведенным из
`OFFICE3D_HERMES_KEY_SECRET`; главный агент видит инструменты команды,
остальные — только список команды (`office_team_list`). Адрес сервера Office3D
прописывает в `config.yaml` каждого профиля (`mcp_servers.office3d_team` у
главного, `mcp_servers.office3d` у остальных), а токен — в его `.env`
(`OFFICE3D_MCP_TOKEN`). Это происходит при подключении к Hermes, при найме,
при первом появлении профиля в списке и при сверке раз в десять минут — так
же подхватываются профили, созданные мимо офиса. Hermes подключает новый
сервер сам, примерно за минуту, без перезапуска.

Профили Hermes в одном контейнере — не граница безопасности: агент с
терминалом может прочитать чужие файлы в `/opt/data`. Поэтому решающая защита
здесь — согласие руководителя: даже от чужого имени агент может только
предложить, а не нанять или уволить.

## Переменные окружения

| Переменная | Где | Назначение |
|---|---|---|
| `HERMES_API_URL` | office3d | API-сервер Hermes. Если задана — Hermes становится бэкендом по умолчанию. |
| `HERMES_API_KEY` | office3d, hermes | `API_SERVER_KEY` главного профиля, не короче 16 символов. |
| `HERMES_DASHBOARD_URL` | office3d | Панель Hermes (в Docker — `http://hermes:9120`, это hermes-gate). Без неё в офисе только главный агент. |
| `HERMES_DASHBOARD_TOKEN` | office3d, hermes, hermes-gate | Токен сессии панели. |
| `OFFICE3D_HERMES_KEY_SECRET` | office3d | Из него выводятся ключи профилей агентов; хранить сами ключи не нужно. Смена секрета перевыпускает все ключи при следующем обращении. |
| `HERMES_IMAGE_TAG` | compose | Версия образа Hermes; при обновлении из офиса её переписывает сервис `updater`. |
| `OFFICE3D_UPDATER_TOKEN` | office3d, updater | Токен между офисом и сервисом обновлений, не короче 32 символов. |
| `OFFICE3D_UPDATER_URL` | office3d | Сервис обновлений (в compose — `http://updater:3020`). Без него офис не предлагает обновления. |
| `OFFICE3D_MCP_HOST`, `OFFICE3D_MCP_PORT` | office3d | Где слушает MCP-сервер Office3D (по умолчанию `127.0.0.1:3010`; в compose — `0.0.0.0:3010` во внутренней сети). |
| `OFFICE3D_MCP_URL` | office3d | Адрес, по которому Hermes достаёт до MCP-сервера (в compose — `http://office3d:3010`). |
| `OFFICE3D_TIMEZONE` | office3d | Часовой пояс рабочих часов и дневного бюджета автономии (например, `Europe/Moscow`); по умолчанию — пояс сервера. |
| `GATEWAY_MULTIPLEX_PROFILES=true` | hermes | Один шлюз обслуживает все профили. Задано в compose и в `hermes-local`; без этого свежая установка не обслуживает новых агентов. |

## Проверка

- `npm run doctor` (или `node scripts/office3doctor.mjs`) проверяет ключи,
  доступность API и панели.
- Модульные тесты адаптера работают против поддельного Hermes:
  `npx vitest run tests/unit/hermesAdapter.test.ts tests/unit/hermesGate.test.ts`.
- Проверка на настоящем Hermes — `tests/unit/hermesRealIntegration.test.ts`.
  Модель не нужна: `scripts/dev/stub-openai-model.mjs` — сценарная модель,
  совместимая с OpenAI. Порядок:

  ```bash
  node scripts/dev/stub-openai-model.mjs            # модель на :18900
  # в ~/.hermes/config.yaml: model.provider=custom,
  #   model.base_url=http://127.0.0.1:18900/v1, approvals.mode=manual
  npm run hermes-local                              # или вручную gateway + dashboard
  OFFICE3D_HERMES_ITEST=1 HERMES_API_URL=http://127.0.0.1:8642 \
    HERMES_API_KEY=... HERMES_DASHBOARD_URL=http://127.0.0.1:9119 \
    HERMES_DASHBOARD_TOKEN=... OFFICE3D_HERMES_KEY_SECRET=... \
    npx vitest run tests/unit/hermesRealIntegration.test.ts
  ```

  Тест проверяет потоковый ответ, запрос одобрения опасной команды и отказ,
  создание агента-профиля, разговор с ним и удаление, ключи и модели
  провайдеров, миссию в `SOUL.md`, выполнение задачи с доски диспетчером и
  подключение Hermes к MCP-серверу Office3D от имени каждого агента,
  совещание с живыми репликами, цепочку одобрений и установку навыка из
  Skills Hub. Для проверки MCP в Hermes должен быть пакет `mcp` (в
  Docker-образе он есть; при установке из исходников —
  `pip install 'hermes-agent[mcp]'`).

## Обновления Hermes

В Docker-установке офис сам следит за новыми версиями Hermes. Когда выходит
релиз новее запущенного, в офисе появляется карточка «Доступна новая версия
Hermes … — Обновить / Позже». «Позже» скрывает эту версию на сутки.

«Обновить» делает сервис `updater` (контейнер `office3d-updater`):

1. Загружает новый образ; Hermes пока работает.
2. Останавливает `hermes-gate` и `hermes`, чтобы агенты не работали во время
   обновления. Простой — примерно 1–3 минуты.
3. Сохраняет том `hermes-data` в архив. Архивы лежат в томе `hermes-backups`,
   хранятся три последних.
4. Записывает новую версию в `HERMES_IMAGE_TAG` в `.env`, так что следующий
   `docker compose up` её сохранит, и поднимает оба сервиса.
5. Проверяет, что API Hermes и hermes-gate отвечают три раза подряд в
   пределах трёх минут.

Если проверка не прошла, сервис восстанавливает данные из архива, возвращает
прежнюю версию в `.env` и поднимает её. Карточка сообщает «Версия … не
заработала — возвращена …», и эту версию офис больше не предлагает. Если не
поднимается и прежняя версия, карточка просит вмешаться администратора.
Архив остаётся в `hermes-backups`.

Сервис обновлений — единственный контейнер с доступом к сокету Docker. Он
не публикуется наружу и принимает только запросы с `OFFICE3D_UPDATER_TOKEN`
(`openssl rand -hex 32`). Без него офис обновлений не предлагает, и Hermes
обновляется вручную: сменить `HERMES_IMAGE_TAG` и выполнить
`docker compose up -d hermes hermes-gate`.

Проверка механизма на настоящем Docker с тестовыми образами:
`OFFICE3D_DOCKER_ITEST=1 npx vitest run tests/unit/hermesUpdaterDocker.test.ts`.

## Резервные копии

Всё состояние агентов — в томе `hermes-data` (`/opt/data`): профили, память,
сессии, навыки, канбан. Состояние офиса — в томе `office3d-state`. Перед
каждым обновлением из офиса данные Hermes архивируются в том `hermes-backups`.
Копируйте оба, остановив контейнеры, либо используйте `hermes backup`
внутри контейнера Hermes.

## Откат на OpenClaw

В `.env`: `OFFICE3D_GATEWAY_ADAPTER_TYPE=openclaw`, `OFFICE3D_GATEWAY_URL` и
`OFFICE3D_GATEWAY_TOKEN` шлюза OpenClaw; затем `docker compose up -d office3d`.
Данные Hermes при этом не трогаются, и вернуться обратно можно тем же способом.

## Прежние механизмы OpenClaw

Магазин навыков офиса и установка навыков в файлы (`~/.hermes/skills` на
машине Office3D) остались для OpenClaw. Для Hermes навыки ставятся только
через «Навыки Hermes» в настройках агента, то есть через самого Hermes.
