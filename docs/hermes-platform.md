# Office3D на Hermes Agent: архитектура

Этот документ описывает, как Office3D работает поверх [Hermes Agent](https://github.com/NousResearch/hermes-agent)
от Nous Research: какие части делает сам Hermes, какие — Office3D, и почему.
OpenClaw остаётся поддерживаемым бэкендом; Hermes — бэкенд по умолчанию.

## Принципы

1. **Не дублировать Hermes.** Агенты, память, навыки, инструменты, сессии, расписание,
   канбан с диспетчером, одобрения опасных действий и провайдеры моделей — это Hermes.
   Office3D — офис, в котором эту работу видно и которым удобно управлять: 3D-сцена,
   голос, организация (миссия, права, бюджет, совещания).
2. **Агент = профиль Hermes.** У каждого агента свой `HERMES_HOME`: память, навыки,
   ключи, `SOUL.md`, модель. Hermes прямо предупреждает, что два агента на одном
   профиле портят друг другу память.
3. **Секреты не покидают сервер.** Браузер не видит ни одного ключа Hermes.
4. **Честные ошибки.** Метод, которого Hermes не поддерживает, отвечает
   «не поддерживается», а не имитирует успех.

## Компоненты

```
Браузер ──WS (протокол шлюза)──► Office3D: server/index.js
                                   ├─ gateway-proxy ──► адаптер Hermes (в процессе)
                                   │                     └─ server/hermes/* ──HTTP──► Hermes
                                   ├─ слой организации (миссия, права, бюджет, совещания)
                                   └─ голос (распознавание и речь через провайдеров)

Hermes (официальный образ, один контейнер)
  ├─ API :8642    /v1/*, /api/sessions/*, /api/jobs/*, /p/<профиль>/…   ключ профиля
  └─ панель 127.0.0.1:9119  /api/profiles/*, /api/env, /api/plugins/kanban/*
       ▲
hermes-gate :9120 (в сетевом пространстве контейнера Hermes)            токен сессии панели

Сервис обновлений (отдельный контейнер, только внутренняя сеть)
```

### Один процесс Hermes на все профили

Hermes по умолчанию обслуживает все профили одним шлюзом («multiplexing»):
запросы к профилю `coder` идут на `/p/coder/v1/...` того же порта и
подписываются ключом `API_SERVER_KEY` из `.env` этого профиля. Новый профиль
подхватывается при пересканировании (не дольше 30 секунд) без перезапуска.

### Панель Hermes и hermes-gate

Панель Hermes на адресе вне loopback требует интерактивного входа (пароль или
OAuth, cookie) и не принимает машинный токен сессии; на loopback принимает, но
тогда доступна только из своего контейнера. Поэтому панель слушает
`127.0.0.1:9119`, а рядом, в сетевом пространстве контейнера Hermes, работает
`hermes-gate` (тот же образ Office3D, `server/hermes-gate.js`). Он пропускает
запрос только с токеном сессии — для всех маршрутов, включая маршруты
плагинов, которые сама панель не проверяет.

### Мультиплексирование и имена профилей

`GATEWAY_MULTIPLEX_PROFILES=true` задаётся явно: сам Hermes включает режим
только для установки, где профилей уже несколько, и свежая установка иначе не
обслуживает новых агентов.

Каждый нанятый агент получает имя профиля, которого ещё не было
(`<имя>-<6 знаков>`): работающий шлюз держит открытой базу состояния
удалённого профиля, и новый профиль под тем же именем отвечает ошибкой
«state.db was replaced underneath the gateway» до перезапуска Hermes.

### Ключи профилей

Office3D не хранит ключи профилей. Ключ профиля — это
`HMAC-SHA256(OFFICE3D_HERMES_KEY_SECRET, "office3d:hermes-profile:" + имя)`;
Office3D записывает его в `.env` профиля через панель (`PUT /api/env?profile=`)
при создании профиля и сверяет при первом обращении. У профиля `default`
ключ — `API_SERVER_KEY` контейнера. Смена мастер-секрета перевыпускает все ключи.

### Что чем реализуется

| Office3D (протокол шлюза) | Hermes |
|---|---|
| `agents.list/create/update/delete` | профили панели: `/api/profiles`, `soul`, `model`, `description` |
| `chat.send`, стриминг, вызовы инструментов | `POST /v1/runs` + `GET /v1/runs/{id}/events` (SSE) |
| `chat.abort` | `POST /v1/runs/{id}/stop` |
| одобрения опасных действий | событие `approval.request`, `POST /v1/runs/{id}/approval` |
| `chat.history`, `sessions.*` | `/api/sessions/*` |
| `cron.*` | `/api/jobs/*` |
| `models.list` | `/api/model/options` |
| задачи | канбан Hermes `/api/plugins/kanban/*` |
| `usage.cost`, `sessions.usage` (аналитика расходов) | `/api/analytics/usage` и `/api/sessions` каждого профиля |
| `skills.status/update`, `hermes.skills.*` | `/api/skills`, `/api/skills/toggle`, `/api/skills/hub/*` |
| `wake` | обзор главного агента, как `org.autonomy.runNow` |

Ход агента — это *run*: он переживает обрыв соединения (события буферизуются пять
минут), его можно остановить, у него есть одобрения и учёт токенов. Поле
`instructions` запуска — разовая системная инструкция: через неё в каждый ход
подаются файлы агента, которым в Hermes нет места (`IDENTITY.md` и другие), и
текущая миссия организации.

## Организация

- **Миссия** хранится в Office3D и закреплена над доской. Вместе с правилами роли
  она записана блоком в `SOUL.md` каждого агента, между маркерами
  `<!-- office3d:organization … -->` и `<!-- /office3d:organization -->`: так её
  видят все разговоры агента — чат в офисе, задачи диспетчера, расписание.
  Собственный характер агента в `SOUL.md` остаётся его: офис показывает и
  сохраняет только его, а блок дописывает сам. Hermes запоминает системный
  промпт сессии при её создании, поэтому в уже идущий разговор офис
  дополнительно подаёт текущую миссию в `instructions` каждого запуска. Блок
  выравнивается при каждом подключении к Hermes и при смене миссии; главному
  агенту при этом включается набор инструментов `kanban`.
- **Задачи** — канбан Hermes: диспетчер сам запускает назначенного агента, следит за
  ним, повторяет после сбоев, ведёт журнал. Ставить задачи могут только главный
  агент и человек; задача, созданная другим агентом, переводится в «Разбор» как
  предложение, и её принимает главный или человек.
- **Найм и увольнение** — только главный агент и только с согласия человека:
  главный называет причину, в офисе появляется карточка «Одобрить / Отклонить»,
  одобренное выполняет сам Office3D, а решение приходит главному в чат.
  Инструменты команды главному даёт MCP-сервер Office3D (`server/hermes/mcp.js`,
  `server/hermes/team.js`): внутренний порт, токен на каждого агента, выведенный
  из общего секрета; у остальных агентов — только список команды.
- **Автономия** (`server/hermes/autonomy.js`) — два режима: главный по
  расписанию пересматривает миссию и доску, или его зовут, когда доска пустеет
  или появляются предложения. В обоих: рабочие часы, дневной бюджет (рост
  стоимости всех профилей по `/api/analytics/usage` с местной полуночи), пауза
  обзоров и доски (`kanban.dispatch_profiles`). Собственный разборщик Hermes
  выключен: «Разбор» — работа главного агента.
- **Совещания** (`server/hermes/meetings.js`) ведёт сервер. Главный агент
  открывает совещание, участники по очереди отвечают настоящими репликами
  модели, каждый в своей сессии совещания и со стенограммой перед глазами.
  Итог главного становится задачами на доске. Офис показывает совещание в
  своей 3D-переговорной (`useHermesMeetingController` переводит его в формат
  стендапа), а главный агент может созвать его сам (`office_call_meeting`).
- **Опасные действия** (`server/hermes/approvals.js`): запрос сотрудника
  сначала решает главный агент инструментом `office_decide_approval`; важное
  он передаёт человеку карточкой и голосом. Если главный не решил вовремя,
  запрос уходит человеку. Все решения пишутся в журнал.

## Голос

Провайдеры распознавания и синтеза речи подключаются через общий интерфейс
(`src/lib/voice/providers.ts`). Их три: ElevenLabs, любой сервер с аудио-API
OpenAI (путь к бесплатному локальному голосу) и OpenClaw (только
распознавание). Выбор делается переменными окружения сервера.

У каждого агента свой голос (`src/lib/voice/agentVoices.ts`). Alt+Shift
отправляет сказанное всем агентам. Реплики совещаний, объявления главного и
его предложения по команде тоже озвучиваются. Диалог с главным идёт с
уточняющими вопросами и подтверждением — это правило в его `SOUL.md`.

## Обновления Hermes

Внутри Docker Hermes не обновляет сам себя — обновление означает новый образ.
Office3D раз в шесть часов спрашивает сервис обновлений (`server/updater`,
контейнер `office3d-updater`): какая версия запущена и какие релизы новее
(Docker Hub). Затем показывает «Обновить / Позже»; «Позже» скрывает версию на
сутки.

Сервис обновлений работает только во внутренней сети, с токеном, и единственный
имеет доступ к Docker. Он умеет лишь проверить версии и обновить Hermes:
загрузить образ, остановить `hermes` и `hermes-gate`, сделать резервную копию
тома данных, переписать `HERMES_IMAGE_TAG` в `.env` и поднять сервисы через
тот же compose-проект. После этого проверяется, что API Hermes и hermes-gate
отвечают несколько раз подряд. При неудаче он восстанавливает данные из копии
и поднимает прежний образ. Версию, которая не заработала, офис повторно не
предлагает.

## Безопасность

- Наружу публикуется только Office3D (с `STUDIO_ACCESS_TOKEN`); порты Hermes
  доступны только во внутренней сети Docker.
- Маршруты канбана в панели Hermes не проверяют доступ (так задумано в Hermes),
  поэтому панель нельзя публиковать ни при каких настройках.
- `API_SERVER_KEY` обязателен даже на loopback: API Hermes исполняет команды в
  терминале.

## Откат на OpenClaw

`OFFICE3D_GATEWAY_ADAPTER_TYPE=openclaw` и адрес шлюза OpenClaw в `.env`,
перезапуск Office3D. Данные Hermes в его томе при этом не трогаются.
