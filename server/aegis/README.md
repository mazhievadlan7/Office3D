# AEGIS — легальное ядро (Phase 0)

Это контрольный слой авторизованного тестирования безопасности: **замок**, который
по ТЗ должен работать раньше любого агента («ни один агент не запускается, пока не
работает scope-enforcement», §0/§9). Ядро отвечает ровно на один вопрос — *«можно
ли это действие прямо сейчас, против этой цели, в рамках активного авторизованного
engagement?»* — и записывает каждый ответ. Никаких действий над целями здесь нет.

## Что входит

| Модуль | Роль |
|--------|------|
| `ip.js` | Строгий разбор IPv4/IPv6 и проверка вхождения в CIDR. Всё неоднозначное → отказ. |
| `scope.js` | Модель активов (domain/ip/cidr/url) и сопоставитель цели со scope, **default-deny**. Домен матчится только против доменных активов, IP — только против ip/cidr; домены здесь не резолвятся (это делает egress-firewall). |
| `engagement.js` | Жизненный цикл engagement: `draft → authorized → active → stopped/completed`. Активация — **ручное подтверждение заказчика**. Kill-switch: глобальный и по engagement. |
| `store.js` | Атомарное хранилище состояния (temp-file + rename, режим 0600). |
| `audit.js` | Неизменяемый **hash-chained** леджер (JSONL). `verify()` находит подделку/удаление строки. |
| `egress.js` | Компиляция активного scope в allowlist для egress-firewall (nftables/eBPF). |
| `preflight.js` | Единый шлюз: kill → active → scope → rate-limit → destructive-policy → audit. Deny-by-default, наружу не бросает (баг может только «закрыться», не «открыться»). |
| `index.js` | Сборка ядра: `createAegisCore({ dataDir })`. |

## Как это защищает

- **Default-deny везде.** Цель разрешена, только если однозначно совпала с активом
  активного engagement. Любая ошибка разбора → отказ.
- **Двойной барьер.** `scope.js` проверяет *заявленную* цель; egress-firewall на узле
  (из `egress.js`) режет *фактический* исходящий трафик. DNS-ответ не расширяет периметр.
- **Ручная активация.** Ничего не активируется само: `activate()` требует `confirm:true`
  и записывает, кто и когда.
- **Kill-switch.** Глобальный или по engagement — мгновенно, проверяется перед каждым действием.
- **Неизменяемый аудит.** Каждое решение (allow и deny) и каждая смена состояния —
  строкой в hash-chain; изменить прошлое незаметно нельзя.

## Статусы (§11)

- **IMPLEMENTED + TESTED (unit):** scope-матчинг, разбор IP/CIDR, жизненный цикл
  engagement, kill-switch, hash-chain аудит, pre-flight, компиляция egress-allowlist.
- **DESIGNED (реализуется на сервере):** применение egress-firewall на узле
  (nftables/eBPF из сгенерированного artifact); живая проверка владения активом
  (DNS TXT / файл-токен / WHOIS) в Authorization Gateway — здесь заложен слот
  `verification` в записи авторизации и ручной гейт активации.
- **Намеренно НЕ здесь:** Execution Plane (запуск инструментов). Он подключается к
  этому ядру следующим и **обязан** звать `preflight.check()` перед любым действием.

## Границы (обязательны для любого будущего модуля)

Знать техники и оркестровать существующие легальные инструменты — можно; действовать
— только по авторизованным целям, внутри активного scope, под аудитом. Никакой работы
в обход scope-гейта. Эти правила — сквозные: новый модуль нельзя добавить в обход
периметра (§12).
